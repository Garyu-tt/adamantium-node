# Adamantium-node R05 — auditable durable factory and Universal Graph IR projection

**Stage:** draft/source implementation. R01–R04 are isolated infrastructure and tests, R05 adds an explicitly selected append-only local journal and independent G0 preview. None of these components is an authorized production Lifecycle deployment.

## Durability and recovery contract

Each candidate is a strict `adamantium.node-factory/1` contract generated by R02. The journal is created under a **new** explicit root; it never overwrites `~/.node-red` or production data. Four advisory event kinds are supported: `factory.proposed`, `factory.verified`, `factory.rejected`, `factory.promotion.requested`. No `approved`, `installed` or `published` event exists.

Every event has a sequence, previous head, timestamp, strict body, and SHA-256 hash of the complete unsigned event. Appends require both the expected sequence and current head (CAS). A process-local exclusive writer lock (`writer.lock`, create-exclusive), fsync, complete readback and a refreshed `view.json` provide a durable single-host audit and an observer-friendly snapshot. If the lock survives a crash, attempts **fail closed** until the operator examines the state. A partial final line fails closed; do not silently truncate it.

State is recovered solely by replaying `journal.jsonl`, checking each typed event and hash, not trusting a materialized view. The snapshot `view.json` exists for UI and is a cache: it is not the authority.

**Limit:** a local SHA-256 chain is tamper-evident only relative to an independently held head. Anyone able to rewrite the entire journal and remove external evidence may be able to roll history back. `trustedSequence` + `trustedHead` lets an independent witness pin a previously observed segment. R05 does **not** deploy that independent witness, sign events, distribute replicas, or make the journal immutable.

## Real proof path

```text
factory.proposed → deterministic Node-RED package source SHA-256
  → factory.verify (R04 real disposable Node-RED 5 pipeline)
  → proof includes installed hashes, actual message execution and rollback
  → compare proof against original package bytes
  → append factory.verified + whole bounded proof and fsync
  → optional factory.promotion.requested (effect=false)
  → MAS Policy / Lifecycle (separate capability, not available in R05)
```

R05's independent `mechanicus.universal-graph/1` projection describes contract generation, packaging, isolated verification and audit as four typed capability nodes with three typed data edges. It is **structural only**: graph references grant no capability; the projection is not native G0 compiler output, is not a valid authorization token and is not compiled automatically into the running Node-RED palette.

## Local commands

Run Node.js >=22.9 from the repository's root. Choose a new *explicit* ledger root:

```sh
node adamantium/node-factory/cli-r05.mjs init /path/to/new-ledger
node adamantium/node-factory/cli-r05.mjs propose /path/to/new-ledger adamantium/node-factory/examples/demo-uppercase.json
node adamantium/node-factory/cli-r05.mjs inspect /path/to/new-ledger
node adamantium/node-factory/cli-r05.mjs graph /path/to/new-ledger candidate-<id-from-propose>
node adamantium/node-factory/cli-r05.mjs verify /path/to/new-ledger candidate-<id-from-propose>
node adamantium/node-factory/cli-r05.mjs promotion-request /path/to/new-ledger candidate-<id-from-propose>
```

Without the repo's existing locked Node-RED 5 npm dependencies, verification fails; only the pure contract/journal/graph preview functions can work offline. Verification runs a **new** temporary Node-RED instance and deletes it after proof; it never targets the visible studio's running flows.

## Visual control

On an owner-authorized Windows studio, configure a *read-only* Node-RED flow `watch → file in → json → debug` pointing to the journal's `view.json`. That flow displays every finished append in the Debug sidebar without giving the graphical editor a journal write capability. The user may view the graph, its transitions and audit status while the CLI operates.

## Tests and gates

- Linux and Windows Node 22/24: replay, fsync/CAS, stale writes, locked writer, full-head rollback pinning, torn tail, forged proof denial and strict G0 structural preview.
- Linux and Windows Node 22 with Node-RED 5 dependencies: real verification receipt persisted, promotion request advisory only, reopening and witness pin consistency.
- No merged code, no automatic publication, no privileged apply, no long-running daemon or off-host replication is introduced here.
